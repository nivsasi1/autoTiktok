# ארכיטקטורה טכנית ועלויות

*נכון לאוגוסט 2026. כל המספרים ממקורות רשמיים של הספקים (פירוט במחקר המקורי).*

---

## סטאק מומלץ (סולו-דבלופר)

- **Frontend:** Next.js/React, עברית-RTL מלא, גלריה מהירה במובייל (virtualized grid, lazy loading). זה המוצר — רוב ההשקעה הולכת לכאן.
- **Backend:** Node/TypeScript (או Python/FastAPI), Postgres + **pgvector** (וקטורים 512D; בסקייל הזה אפילו brute-force פר אירוע הוא מילישניות — אין צורך ב-vector DB ייעודי).
- **אחסון:** **Cloudflare R2** (פשוט, S3-compatible, אפס egress, ‎$0.015/GB) או **Backblaze B2** (הכי זול, ‎$0.00695/GB, egress חינם דרך Cloudflare). לא S3 — ה-egress יהרוג את המרווח במוצר שבו 150 אורחים גוללים כל גלריה.
- **פייפליין תמונות:** יצירת 3 גרסאות מראש עם sharp/libvips בהעלאה (thumb ~100KB, display ~2500px, social) — עלות שולית ~0, ‎+~1GB אחסון לאירוע.
- **תור עבודות:** אינדוקס פנים כ-background job (BullMQ/pg-boss) — חתונה של 600 תמונות מתאנדקסת בדקות.
- **אירוח:** Hetzner CX22 ‎€3.79/חודש מספיק להתחלה (אפליקציה + Postgres + workers); Cloudflare מקדימה לכל מה שפונה לאורחים.

## זיהוי פנים — בחירת ספק

| אפשרות | סטטוס | הערות |
|---|---|---|
| **AWS Rekognition** ✅ | הבחירה ל-MVP | היחיד מהעננים הגדולים שפתוח בלי אישור מיוחד. Collection פר אירוע. |
| Azure Face | ❌ בפועל | Limited Access מ-2022 — דורש אישור של Microsoft; סיכון דחייה לסולו-דב לא מוכר. |
| Google | ❌ | אין בכלל מוצר face-identity (רק detection). |
| InsightFace (buffalo_l) | ⚠️ מלכודת רישיון | איכות SOTA ורץ על CPU, אבל המשקולות **למחקר בלבד** — שימוש מסחרי דורש רישיון בתשלום (מחיר לא ציבורי). לא לבנות על זה בלי רישיון! |
| CompreFace | ⚠️ | Apache-2.0, docker-compose נוח — אבל לוודא רישיון המודלים המובנים (חלקם מ-InsightFace). |
| DeepFace (FaceNet512/SFace) | ✅ כ-fallback | MIT, איכות מעט נמוכה יותר; טוב לבנצ'מרקים ולמסלול self-host חוקי. |

**המלצה:** להתחיל עם Rekognition (eu-central-1 פרנקפורט; il-central-1 ת"א תומך רק בחלק מהפעולות — לוודא IndexFaces/SearchFacesByImage לפני שמסתמכים). לעבור ל-self-host רק אם הנפח יצדיק משא-ומתן על רישיון InsightFace.

**פרט מימוש חשוב:** SearchFacesByImage מחפש רק את הפנים הגדולות בתמונת השאילתה — לסלפי קבוצתי צריך DetectFaces → crop לכל פרצוף → חיפוש נפרד לכל אחד (עלות זניחה).

**מבנה נתונים:** Collection נפרד פר אירוע = חיפוש תחום, בידוד נתונים, ומחיקת כל הביומטריה של אירוע במחיקת ה-Collection (קריטי משפטית).

## WhatsApp (טבלת-חובה בישראל, אבל כמעט חינם אם בונים נכון)

- מ-1.7.2025 Meta מחייבת **פר הודעת template** (לא פר שיחה). ישראל: **~$0.0056 utility / ~$0.0371 marketing** להודעה.
- **שיחה שהאורח יוזם = חינם לגמרי** (חלון 24 שעות, כולל utility templates בתוכו). ⇒ הארכיטקטורה הזולה: QR / קישור wa.me → האורח שולח סלפי בצ'אט → בוט מחזיר לינק לגלריה האישית. **₪0 עלות Meta.**
- Blast יזום-עסק ל-500 אורחים: **~$2.80** אם ה-template מסווג utility; **~$18.55** אם Meta מסווגת אותו marketing (מ-אפריל 2025 היא מסווגת מחדש בכוח — לנסח template יבש בלי קידום!).
- דרישות חד-פעמיות: אימות עסק ב-Meta (מסמכי עוסק/חברה, 2–5 ימי עבודה; בלי אימות התקרה 250 נמענים/יממה — לא מספיק לחתונה אחת), מספר ייעודי, אישור templates. אחרי אימות: Tier 1 = 1,000 נמענים/יממה (חתונה אחת נכנסת; שתיים באותו יום — צריך עליית tier אוטומטית).
- **Cloud API ישיר, לא BSP** (Twilio/WATI מוסיפים עמלות). לא להשתמש ב-API לא רשמי (Green API וכו') — Meta מוחקת מספרים לצמיתות.
- SMS בינלאומי לא רלוונטי ($0.17–0.26 להודעה לישראל); ספקי SMS ישראליים זולים (₪0.015–0.12) — fallback בלבד, הציפייה בישראל היא WhatsApp.

## אבטחה (מינימום רגולטורי — תקנות אבטחת מידע 2017, רמה בינונית)

- הצפנה at-rest ו-in-transit לכל התמונות והווקטורים.
- בקרות גישה מבוססות-תפקיד (צלם רואה רק אירועים שלו), לוגים לכל גישה לנתונים ביומטריים.
- בידוד פר אירוע + מחיקה אוטומטית בתפוגה (גם ב-storage וגם ב-Rekognition Collection).
- מסמך הגדרות מאגר + נוהל אבטחה כתובים (חובה חוקית), תוכנית תגובה לאירועים ודיווח לרשות להגנת הפרטיות.
